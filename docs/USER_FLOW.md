# USER_FLOW —— 用户交互流程

> 版本 v0.1（2026-11-05，阶段 1 产出，待确认）
> 覆盖主流程、分支流程、异常流程与侧边栏状态机。

## 1. 主流程：选中精读

```
用户在网页选中英文
  │
  ├─ content script 监听 mouseup/selectionchange
  │    ① 立即快照：选中文本、前后上下文（默认各 300 字符）、页面 URL/标题、选区坐标
  │    ② 快照存入内存（不依赖 live Selection，后续 DOM 变化不影响）
  │
  ├─ 显示浮动工具栏（Shadow DOM）
  │    按钮：[AI 精读] [翻译] [解释] [收藏]  [×]
  │    - AI 精读：完整分析（四模式自动路由）
  │    - 翻译：仅双轨翻译的轻请求
  │    - 解释：中等深度（语境义+表达逻辑，不出全量结构分析）
  │    - 收藏：直接以原文入收藏库（稍后补分析）
  │
  └─ 点击「AI 精读」
       → content script 发消息给 Service Worker（携带快照）
       → SW 打开 Side Panel（chrome.sidePanel.open）
       → Side Panel 加载后向 SW 请求当前待分析快照
       → SW 组装 prompt（模式路由 + 上下文包裹）→ 调用 AI（流式）
       → chunk 经 Port 推送到 Side Panel → 渐进渲染
       → 完成：完整结构化结果入内存缓存（供追问与收藏）
```

交互细节：

- 浮动栏出现后：点击页面其他位置 / 滚动 / Esc → 关闭浮动栏（快照已缓存，仍可从侧边栏恢复）。
- 已有侧边栏打开时再次精读：新分析替换当前视图，旧分析（含对话）保留在历史栈，可返回。
- 「翻译」「解释」结果同样进侧边栏，只是展示节不同（轻模式隐藏深度标签页）。

## 2. 入口二：手动输入

```
点击浏览器工具栏图标
  → SW 打开侧边栏（onClicked 事件内，手势合法）
  → 同时尝试 scripting.executeScript 读取当前页选区快照（文本/标题/URL）
       成功 → 侧边栏自动进入分析
       失败（chrome:// 等受限页）→ 侧边栏显示手动输入引导
  → 输入框粘贴英文 → 可选「附带当前网页上下文」→ 进入与主流程相同的分析管线
```

与浮动栏互补：图标入口在受限页面也能打开侧边栏。浮动栏与图标激活两个入口长期并存。

## 3. 入口三：收藏库复习与训练

```
侧边栏切换到「知识库」视图 → 搜索/筛选/浏览收藏
  → 点开条目：原文 + 分析快照 + 个人笔记
  → 「开始练习」→ 基于收藏生成测试/仿写（阶段 6 功能）
```

## 4. 异常与分支流程

| 场景                                        | 处理                                                                                                               |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 选中的不是英文                              | 本地启发式（拉丁字符占比）初判；AI 返回非英语时提示并询问是否继续                                                  |
| 受限页面（chrome:// / 商店页 / PDF 查看器） | content script 注入失败 → 图标角标提示 + 侧边栏手动输入引导                                                        |
| API 未配置                                  | 侧边栏显示配置引导卡片，直达设置页                                                                                 |
| API 请求失败（网络/超时/4xx/5xx）           | 明确错误分类文案；自动重试 1 次（指数退避）；可手动重试                                                            |
| JSON 解析失败                               | 降级链：严格解析 → 宽松提取（截取首尾大括号）→ 重试 1 次（提示模型"仅输出 JSON"）→ Markdown 纯文本兜底渲染，不白屏 |
| 流式传输中断                                | 保留已渲染部分 + 「继续生成」按钮（续传语义由 SW 处理）或重新分析                                                  |
| 用户连点浮动栏                              | 分析进行中禁用再次发起；同选区 500ms 内重复点击去重                                                                |
| 选区为空 / 仅空白字符                       | 不显示浮动栏                                                                                                       |
| 选区超长（>2000 字符）                      | 提示将截断；上下文窗口按配置截断                                                                                   |
| 切换标签页                                  | 快照与分析会话按标签页绑定；切回恢复各自状态                                                                       |

## 5. 侧边栏布局（分析视图）

```
┌─────────────────────────────────┐
│ 原文（可折叠，始终置顶）            │  ← 点击词汇高亮联动意群
│ 页面名 · 模式标签 · [重新分析]      │
├─────────────────────────────────┤
│ [概览][结构][语法][词汇][搭配][表达][对话] │  ← Tab
│                                 │
│  概览（默认）：                    │
│   · 结构直译                      │
│   · 自然意译                      │
│   · 最终理解（作者真正想表达什么）    │
│   （流式渐进出现）                 │
│                                 │
│  结构：意群拆解块 + 句子骨架          │
│  语法：逐点"为什么"解析（折叠列表）    │
│  词汇：重点词卡片（词性/构词/搭配/近义）│
│  搭配：固定搭配与习语解析             │
│  表达思维：中英差异与表达习惯          │
│  对话：追问历史 + 快捷问题           │
├─────────────────────────────────┤
│ [追问输入框............] [发送]    │
│ [收藏 ☆] [复制 ⧉] [库 📚]         │
└─────────────────────────────────┘
```

原则：概览先行，深度折叠；每节独立加载/失败/空状态；窄边栏自适应。

## 6. 收藏流程

```
分析完成 → 底部「收藏」
  → 默认收藏：原文 + 完整分析快照 + 来源 + 时间
  → 可选：打标签（P1）、补一句笔记（P1）
  → Toast 提示成功，点击 Toast 跳转知识库视图

未分析直接收藏（浮动栏「收藏」按钮）：
  → 原文入库存为 pending 条目（无分析快照）
  → 知识库中可补触发分析
```

## 7. 追问对话流程

```
用户在输入框提问（或点快捷问题）
  → SW 组装对话 prompt：system + 原文 + 上下文 + 既有分析摘要 + 对话历史（滚动窗口，默认保留最近 10 轮）
  → 流式返回追加到对话 Tab
  → 「重新分析」重置对话（旧对话随旧分析归档，可返回查看）
```

追问示例（需求原文列举）：为什么这里用 likely 而不是 probably / scammy 怎么构成的 / 换种表达怎么写 / 给我几个类似例子 / 用更简单的英语解释一遍。

## 8. 关键状态定义（Side Panel）

| 状态        | 触发                     | 展示                                     |
| ----------- | ------------------------ | ---------------------------------------- |
| `idle`      | 无待分析内容             | 空态引导（使用说明 + 手动输入框）        |
| `routing`   | 请求已发出，等待模型首包 | 骨架屏 + "正在分析…"                     |
| `streaming` | 首包到达                 | 已到内容渐进渲染 + 流式光标              |
| `done`      | 完成                     | 完整标签页可用                           |
| `degraded`  | JSON 降级为 Markdown     | 内容正常展示 + 角标"简化视图" + 重试按钮 |
| `error`     | 请求失败/解析彻底失败    | 错误分类文案 + 重试按钮                  |

每个 Tab 节内容独立子状态：一节解析失败不影响其余节展示。
