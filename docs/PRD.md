# PRD —— LinguaLens 产品需求文档

> 版本 v0.1（2026-11-05，阶段 1 产出，待确认）
> 一句话定位：选中即精读的 AI 英语深度阅读助手——不止翻译，讲透英语为什么这样表达。

## 1. 背景与问题

中文用户阅读英文网页（Hacker News、GitHub 文档、英文博客、Reddit）时，现有工具基本停在"翻译"层面。翻译解决了"这句英文是什么意思"，但没有解决三个更关键的问题：

1. **为什么这样表达**——为什么用 likely 而不是 probably？为什么这个词放这个位置？
2. **英语的组织逻辑**——意群怎么切、句子骨架是什么、中文为什么要调整语序。
3. **表达习惯与语感**——scammy 这种临时造词的修辞效果、on steroids 的习语气场、括号补语的讽刺语气。

LinguaLens 的目标就是把"翻译插件"升级为"精读教练"：用户读完一次分析，应该能不看翻译重新理解整句话，并逐步把这些表达内化成自己的写作能力。

## 2. 目标用户

以中文为母语的英文阅读者，核心画像两类：

| 画像 | 典型行为 | 核心痛点 |
|------|----------|----------|
| 开发者/技术人员 | 读 HN、GitHub README、英文文档 | 句子能机翻但说不清语法逻辑；写作时不敢仿用读到的表达 |
| 普通英语学习者 | 读新闻、Reddit、产品介绍 | 词典查得到单词但拼不出句意；长期读英文但提升慢 |

共同前提：用户会主动选中读不懂或值得学的英文，有沉淀和复习的需求。

## 3. 使用场景

- 阅读 Hacker News / Reddit 的评论与讨论（口语化、缩略、反讽多）
- 阅读 GitHub README、技术文档（长句、被动语态、插入语多）
- 阅读英文新闻与博客（复合句、修辞多）
- 与外国人文字交流后复盘表达
- 学习英文博客写作，仿写读到的句式

## 4. 产品原则（贯穿所有功能的设计约束）

1. 不做只给中文翻译的工具；不做词典释义搬运。
2. 一切分析必须结合选中文本的当前上下文，脱离语境的通用解释降级为辅助信息。
3. 必须解释语法成分在句子中的作用（"修饰谁、为什么放这里"），而不是只贴标签（"这是定语从句"）。
4. 翻译必须双轨：结构直译（保留英文组织方式）+ 自然意译（符合中文习惯）。
5. 解释不确定的语言点时必须标注存在其他可能，禁止编造词源和语法规则。
6. 区分三类知识：语法规则（确定）、语言习惯（惯例）、作者个人风格（个案）。
7. 循序渐进：先骨架后细节，先概览后深挖，默认不一次性倾倒全部内容。
8. 用简单例句解释复杂语言知识。
9. 默认只上传用户选中的文本与必要上下文，不做未授权的网页内容外发。
10. 输出面向渲染的结构化数据，不做一大段文字糊脸。

## 5. 核心体验（用户旅程）

```
选中英文 → 快照(文本+上下文+页面信息) → 浮动工具栏
  → 「AI 精读」打开侧边栏 → 自动判断 单词/短语/句子/段落 模式
  → 流式返回结构化分析 → 按标签页渐进展示
  → 围绕原文连续追问（继承上下文）
  → 一键收藏进本地知识库 → 后续基于收藏生成练习与仿写
```

三种入口互补：选中精读（主路径）、手动粘贴输入（动态网页选区失败/受限页面的兜底）、从收藏库复习。

## 6. 功能范围概览

完整功能拆解见 `FEATURE_LIST.md`。第一版七大模块：

| 模块 | 一句话 |
|------|--------|
| 选区捕获与浮动栏 | 选中即出工具栏，动态网页不丢选区，受限页面有兜底 |
| AI 分析引擎 | 单词/短语/句子/段落四模式，结构化输出，自动路由 |
| 侧边栏阅读界面 | 概览优先、深度折叠、原文对照、流式渲染 |
| 连续追问 | 继承原文与既有分析的多轮对话 |
| 本地知识库 | 收藏、搜索、标签、笔记、导入导出（IndexedDB） |
| 学习训练 | 基于收藏生成测试与仿写练习 |
| 设置与安全 | API 配置、隐私说明、数据清除 |

## 7. 质量验收案例（核心验收标准）

以下四个真实案例是产品分析能力的硬验收，逐条验证，缺一即不合格。

### 案例 1
`Whenever you watch a video on YouTube now, you will likely get an advert for a scammy product.`

必须讲清：
- likely 为什么是副词、修饰什么、与 probably / It is likely that 的差异
- scammy 如何由 scam + -y 构成，临时造词的语感
- scammy 为什么放在 product 前面（定语位置）
- advert for 的含义（"为……打的广告"，for 引出广告对象）
- whenever 的作用（引导让步性时间状语从句，表"每一次都"）
- get an advert 在此处的自然意思（"被推到广告"，get 表遭遇而非获得）
- 直译与意译双轨输出

### 案例 2
`The problem is the scammers only need to get through to a very small percentage of people to make their money back.`

必须讲清：
- the problem is 后接省略 that 的表语从句
- get through to 的实际含义（成功触达/说服某人）
- only 的强调作用（强调成本低、门槛低）
- a very small percentage of people 的量化含义
- to make their money back 与主句的目的关系（不定式作目的状语）
- 整句自然意译（骗子只需触达极少数人就能回本）

### 案例 3
`Glasses that can adapt to any prescription (not how glasses work) and are also sunglasses sometimes.`

必须讲清：
- that 引导定语从句，and 连接从句内两个并列谓语（adapt / are）
- adapt to 在眼镜语境中的含义（适配度数）
- prescription 在此指"验光处方/度数"，不是"处方药"
- not how glasses work 是省略主谓的否定插入语（= this is not how glasses work）
- 括号表达的语气与讽刺效果（点破产品描述违背物理常识）
- 整句自然理解

### 案例 4
`A computer on steroids.`

必须讲清：
- steroids 字面含义（类固醇/激素）
- on steroids 的习语含义（"增强版/放大版"，表示某物是另一物的强化形态）
- 为什么不能逐词翻译
- 典型使用语境（科技/产品对比评价）

## 8. 非目标（第一版明确不做）

- 不做整页翻译、全文对照阅读模式
- 不做离线词典（发音/音标由 AI 返回，不内置词典数据）
- 不做用户账号体系与云端同步（架构预留，见 ARCHITECTURE 数据层设计）
- 不做语音朗读、语音输入
- 不做 Firefox/Safari 适配（Manifest V3 Chromium 优先，API 差异后议）
- 不做自建服务端代理的强制部署（V1 浏览器直连 + 明示风险，代理作为可选项）

## 9. 成功标准

1. 功能验收：四案例全过（上文第 7 节），阶段验收标准见 `ROADMAP.md`。
2. 体验验收：选中到浮动栏出现 < 300ms（本地操作）；精读首屏（翻译+最终理解）流式可读 < 5s（取决于模型）。
3. 安全验收：无 API Key 硬编码；网页内容不作为指令注入；AI 输出安全渲染；提供一键清除本地数据。
4. 工程验收：TypeScript 严格模式零错误；核心逻辑（模式路由、JSON 解析降级、存储层）有单元测试覆盖。
